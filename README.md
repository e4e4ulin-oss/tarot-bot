# Таро-бот

Telegram-бот с раскладами Таро и двумя режимами разбора:

- **Авто-расклад** — бот сам тасует колоду из 78 карт и пишет интерпретацию.
  Значения карт берутся из собственной базы (`bot/tarot/data/cards.json`),
  а связный текст под конкретный вопрос собирает **Grok** (xAI).
- **Авторский разбор** — заявка уходит автору: он раскладывает карты сам, пишет
  разбор (можно с фото расклада), и бот доставляет его клиенту в тот же чат.

Если ключа Grok нет или сервис недоступен, бот не ломается: авто-разбор отдаёт
значения выпавших карт из собственной базы и честно помечает это.

---

## Как пользоваться ботом автору разборов

### Уровни авторского разбора

Заявка начинается с выбора уровня — человек видит цену до того, как напишет вопрос:

| Уровень | Цена | Что входит | Уточнений | Срок |
| --- | --- | --- | --- | --- |
| Лаконичный | 500 ₽ | три карты, короткий ответ по сути | нет | 1 ч |
| Базовый | 700 ₽ | расклад под вопрос, разбор каждой карты | 1 | 2 ч |
| Полный | 1000 ₽ | развёрнутый расклад, разбор по блокам, рекомендации | 3 | 3 ч |

**Срок считается в рабочие часы** — по умолчанию по будням с 9:00 до 18:00 по Москве
(`WORK_START_HOUR`, `WORK_END_HOUR`, `WORK_TIMEZONE` в `.env`). Заявка в 17:50 с двумя
часами срока обещает ответ не в 19:50, а на следующий рабочий день в 10:50; вечерние
и выходные заявки начинают отсчёт с открытия ближайшего рабочего дня, и человеку об
этом прямо сообщают при оформлении. Когда вы нажимаете «взять в работу», бот пишет
конкретное время, к которому нужно ответить.

Выбранный уровень хранится в заявке и виден в уведомлении, в `/orders` и в карточке
`/order N` — вместе с ценой.

**Уточнения бот считает сам.** Кнопка «задать уточняющий вопрос» показывается, только
пока они не исчерпаны, и лимит проверяется ещё раз при нажатии — кнопка из старого
сообщения обойти его не даст. Счётчик лежит в заявке (`followups_used`). Заявкам,
созданным до появления уровней, даётся одно уточнение.

**Оплата — предоплата, вне бота.** Клиенту сказано: когда заявку возьмут в работу,
ему напишут, как оплатить, и разбор готовится после оплаты. Платежей бот не принимает —
реквизиты вы отправляете сами, отвечая на заявку.

Цены и состав уровней меняются без правки кода — см. «Что можно менять без программиста».

### Что видит клиент

Клиент нажимает `/start` и выбирает:

- 🔮 **Авто-расклад** — выбирает раскладку (карта дня, да/нет, три карты,
  отношения, кельтский крест), задаёт вопрос и сразу получает карты и разбор.
- ✍️ **Авторский разбор** — выбирает тему, описывает ситуацию, оставляет заявку
  и ждёт вашего ответа.
- 📜 **Мои расклады** — последние расклады этого человека.

### Как приходит заявка

Каждая заявка приходит всем, кто ведёт разборы: в чат из `ADMIN_CHAT_ID` и в личку
каждому из `ADMIN_IDS`. Выглядит она так:

```
🆕 Заявка №12
От: Мария (@maria)
Тема: Отношения
Вопрос: ...
```

Под ней три кнопки:

| Кнопка | Что делает |
| --- | --- |
| ✅ Взять в работу | помечает заявку как «в работе» — клиенту ничего не уходит |
| ✍️ Ответить | бот попросит написать разбор — следующее ваше сообщение уйдёт клиенту |
| 🚫 Отклонить | заявка закрывается, клиент получает вежливое уведомление |

### Как ответить на заявку

1. Нажмите **✍️ Ответить** под заявкой.
2. Разложите карты, напишите разбор **одним сообщением**.
   Можно отправить фото расклада — с подписью или без; уйдёт ровно то, что вы отправили.
3. Бот перешлёт сообщение клиенту и отметит заявку как отвеченную.
4. Клиент может задать один уточняющий вопрос — он придёт вам в тот же чат
   с пометкой «💬 Уточнение по заявке №…». Ответить на него можно так же:
   кнопка **✍️ Ответить** → сообщение.

Если передумали отвечать — отправьте `/cancel`.

### Команды для вас

| Команда | Что показывает |
| --- | --- |
| `/orders` | список всех открытых заявок с кнопками действий |
| `/order 12` | одна заявка целиком по номеру |
| `/stats` | сколько людей, раскладов и заявок всего |
| `/chatid` | id текущего чата — нужен один раз при настройке |
| `/diag` | проверка настроек и живой тест связи с моделью |
| `/logs` | последние строки журнала; `/logs 120` — сколько строк показать |
| `/update` | подтянуть правки из GitHub и перезапуститься |
| `/restart` | перезапустить бота, например после правки `.env` на сервере |

Последние три команды работают на сервере, где бота ставил `deploy/install.sh`
с флагом `--systemd`: установщик выдаёт боту права ровно на две операции —
обновление кода и перезапуск службы. Если бот запущен иначе, он так и ответит,
вместо того чтобы молчать.

### Что можно менять без программиста

- **Тексты значений карт** — файл `bot/tarot/data/cards.json`. Там для каждой карты
  есть значение в прямом и перевёрнутом положении и ключевые слова. Правится как
  обычный текст; после изменения бот нужно перезапустить.
- **Тексты бота** (приветствие, подсказки, кнопки) — файл `bot/texts.py`.
- **Имя автора разборов** — переменная `AUTHOR_NAME` в `.env`: имя или просто «таролог».
- **Цены уровней авторского разбора** — `AUTHOR_PRICE_SHORT`, `AUTHOR_PRICE_BASE`,
  `AUTHOR_PRICE_FULL` в `.env` (по умолчанию 500, 700 и 1000). Ноль убирает уровень
  из предложения: например, `AUTHOR_PRICE_FULL=0` оставит только два.
  Валюта — `AUTHOR_CURRENCY`.
- **Что входит в каждый уровень, сколько уточнений и часов на ответ** — файл
  `bot/tiers.py`, список `_TIERS`: название, число уточнений, срок в часах и пункты
  «что входит». Числа в списке — те самые, которые бот потом проверяет и показывает,
  так что текст и поведение не разъезжаются.
- **Рабочие часы** — `WORK_START_HOUR`, `WORK_END_HOUR`, `WORK_TIMEZONE` и подпись
  пояса `WORK_TIMEZONE_LABEL` в `.env`. Рабочие дни — понедельник–пятница.
- **Дополнительные условия** — `AUTHOR_PRICE_TEXT` в `.env`: строка под списком
  уровней. Пусто — блок не показывается.
- **Лимит бесплатных авто-раскладов в сутки** — `DAILY_AUTO_LIMIT` в `.env`.

## Для разработчика

### Запуск локально

```bash
git clone https://github.com/e4e4ulin-oss/tarot-bot
cd tarot-bot
./start.sh
```

Скрипт сам создаст venv, поставит зависимости и на первом запуске сделает `.env`
из шаблона — останется вписать `BOT_TOKEN` и запустить его ещё раз.

Вручную то же самое:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env      # заполнить BOT_TOKEN, ADMIN_CHAT_ID, ADMIN_IDS, XAI_API_KEY
.venv/bin/python -m bot
```

Бот работает на long polling — ни домена, ни вебхука не нужно.

### Тесты и линтер

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check bot tests
.venv/bin/ruff format bot tests
```

Покрыто: целостность колоды, вытягивание карт и логика «да/нет», сборка промпта и
резервный разбор без ИИ, жизненный цикл заявки, а также сквозные прогоны апдейтов
через диспетчер с подменённой сессией Telegram (`tests/test_flow.py`) — авто-расклад,
дневной лимит, полный цикл авторской заявки и проверка, что клиент не может нажать
админские кнопки.

### Переменные окружения

Все — в `.env.example`. Минимально необходимые:

| Переменная | Зачем |
| --- | --- |
| `BOT_TOKEN` | токен от @BotFather |
| `ADMIN_CHAT_ID` | чат, куда падают заявки: личка или группа |
| `ADMIN_IDS` | кто ведёт заявки, через запятую — копия приходит каждому |
| `XAI_API_KEY` | ключ Grok; без него авто-разбор работает в резервном режиме |

Необязательные, нужны только при нестандартной установке: `SERVICE_NAME`
(имя службы systemd, по умолчанию `tarot-bot`) и `UPDATE_SCRIPT` (путь к скрипту
обновления, по умолчанию `/usr/local/bin/tarot-update`) — их использует команда
`/update` и `/restart`.

Секреты в репозиторий не коммитятся: `.env` в `.gitignore`.

### Структура

```
bot/
├── __main__.py        точка входа, сборка Bot/Dispatcher
├── config.py          настройки из окружения (pydantic-settings)
├── texts.py           все пользовательские тексты
├── keyboards.py       инлайн-клавиатуры
├── states.py          состояния FSM
├── filters.py         фильтр доступа автора
├── tarot/             колода, раскладки, вытягивание карт, рендер
│   └── data/cards.json  78 карт с русскими трактовками
├── services/          клиент Grok и интерпретатор с резервным режимом
├── db/                модели, сессия, репозиторий (весь SQL — здесь)
├── middlewares/       сессия БД, регистрация пользователя, антифлуд
└── handlers/          common → admin → auto → author → fallback

deploy/
├── install.sh         установка и обновление на сервере
├── autoupdate.sh      проверка GitHub по таймеру (копия: /usr/local/bin/tarot-update)
└── tarot-bot.service  юнит systemd для ручной установки
```

Роутеры подключаются в этом порядке; `fallback` — последним, иначе он перехватил бы
сообщения сценариев.

### Хранилище

По умолчанию SQLite (`data/tarot.db`), таблицы создаются при старте. Для Postgres
достаточно поменять `DATABASE_URL` на `postgresql+asyncpg://...` и добавить `asyncpg`
в зависимости — код на SQLAlchemy 2.0 менять не нужно.

FSM хранится в памяти процесса: после перезапуска незавершённый диалог сбрасывается
(заявки и расклады при этом в БД сохраняются). Для нескольких инстансов подключите
`RedisStorage` в `build_dispatcher`.

### Деплой без сервера (Railway / Render)

Если возиться с VPS не хочется, бот разворачивается из браузера — код берётся прямо
из GitHub, терминал не нужен.

**Railway**: New Project → Deploy from GitHub repo → выбрать `tarot-bot`. Сборка идёт
по `Dockerfile`. В разделе Variables добавить `BOT_TOKEN`, при желании `XAI_API_KEY`,
`ADMIN_CHAT_ID`, `ADMIN_IDS`. В Settings → Volumes подключить том на `/app/data`,
иначе база раскладов и заявок будет теряться при каждом передеплое. Инструкцию `VOLUME`
в Dockerfile Railway не принимает — поэтому её там и нет, том задаётся только в Settings.

**Render** (`render.yaml` в репозитории): New → Blueprint → указать репозиторий.
Сервис создаётся как **worker** (фоновый процесс, не веб-сервис) вместе с диском
на 1 ГБ под базу; значения переменных запрашиваются при создании.

Важно: тип сервиса должен быть именно фоновый процесс. Бот работает через long polling,
он не слушает HTTP-порт, и площадки, которые ждут ответа на HTTP-запрос
(Vercel, Netlify, Cloudflare Workers, Render Web Service), для него не подходят.

### Как править бота с телефона и с компьютера

Рабочий цикл один и тот же с любого устройства: правка → коммит в ветку `main`
на GitHub → сервер подтягивает её сам. Ничего копировать на сервер руками не нужно.

**С телефона — приложение Claude Code.** Создайте сессию и выберите репозиторий
`e4e4ulin-oss/tarot-bot`, дальше опишите задачу словами: «добавь расклад на три
карты», «перепиши приветствие». Правка, проверка тестами и отправка в `main`
происходят в сессии; сервер увидит коммит в течение пяти минут.

**С компьютера — Claude Code в терминале или в десктопном приложении.** Один раз
склонируйте проект (Windows, PowerShell):

```powershell
winget install --id Git.Git --source winget
winget install --id Python.Python.3.12 --source winget
git clone https://github.com/e4e4ulin-oss/tarot-bot
cd tarot-bot
claude
```

Дальше достаточно `cd tarot-bot` и `claude`. Перед отправкой правок полезно
прогнать тесты локально — см. «Запуск локально» и «Тесты и линтер» выше.

**Как правка попадает на сервер.** Служба `tarot-bot-update` раз в пять минут
сверяет ветку `main` с тем, что лежит в `/opt/tarot-bot`, и при расхождении
обновляет код и перезапускает бота. Если новый код не компилируется, обновление
откатывается и бот продолжает работать на прежней версии — сломать работающего
бота правкой с телефона нельзя.

Команды бота в Telegram работают с телефона и без ssh: `/update` подтягивает
правки сразу, `/logs` показывает журнал, `/restart` перезапускает службу.

Не ждать таймер — выполнить на сервере:

```bash
tarot-update                      # подтянуть правки сейчас же
journalctl -u tarot-bot-update -n 20   # что делал таймер
systemctl list-timers tarot-bot-update # когда следующая проверка
```

Выключить автообновление — повторный запуск установки с `--no-autoupdate`.

Важно: сервер следует за `main`. Если правка сомнительная, делайте её в отдельной
ветке и сливайте в `main`, когда проверили.

### Деплой на VPS

Одной командой на Ubuntu/Debian — скрипт скачает код, создаст `.env`, поднимет бота
и включит автозапуск после перезагрузки:

```bash
curl -fsSL https://raw.githubusercontent.com/e4e4ulin-oss/tarot-bot/main/deploy/install.sh \
  | sudo bash -s -- --token ТОКЕН_ОТ_BOTFATHER --systemd
```

Флаг `--systemd` ставит бота в виртуальное окружение Python и заводит службу systemd.
Это верный выбор для сервера, где уже работает что-то ещё: Docker не ставится и
сетевые правила не переписываются, бот занимает около 100 МБ памяти. Логи —
`journalctl -u tarot-bot -f`, перезапуск — `systemctl restart tarot-bot`.

Без флага используется Docker — уместно на сервере, отданном под одного бота.

Код окажется в `/opt/tarot-bot` (меняется флагом `--dir`). Повторный запуск той же
команды обновляет бота до свежей версии, настройки в `.env` при этом сохраняются.
Дополнительные флаги: `--ai` (ключ модели), `--admin-chat`, `--admin-ids`,
`--no-autoupdate` (не подтягивать правки из GitHub по таймеру), `--help`.

Если репозиторий уже склонирован, тот же скрипт работает и локально — тогда он
спросит токен и ключи интерактивно:

```bash
git clone https://github.com/e4e4ulin-oss/tarot-bot
cd tarot-bot
sudo ./deploy/install.sh
```

Дальше:

```bash
docker compose logs -f     # логи
docker compose restart     # после правки .env
git pull && docker compose up -d --build    # обновление
```

**Docker вручную:**

```bash
docker compose up -d --build
```

**systemd:** положите проект в `/opt/tarot-bot`, создайте venv, заполните `.env` и
скопируйте юнит:

```bash
sudo cp deploy/tarot-bot.service /etc/systemd/system/
sudo systemctl enable --now tarot-bot
journalctl -u tarot-bot -f
```

Держите один запущенный экземпляр бота: два процесса с одним токеном будут
конфликтовать за long polling.

### Картинки карт

Расклады до трёх карт бот сопровождает изображениями. Источник по умолчанию —
сканы колоды Райдера-Уэйта с Викисклада (рисунки Памелы Колман Смит, 1909,
общественное достояние). Файлы в репозитории не лежат: ссылку скачивает сам
Telegram, а полученный `file_id` бот кэширует в таблице `card_images`, поэтому
к Викискладу он обращается один раз на карту.

Свои изображения кладутся в `bot/tarot/data/cards/` под именем карты —
`major_00.jpg`, `cups_01.jpg`, `wands_14.jpg` — и имеют приоритет над сканами.
Так колоду можно заменить своими фотографиями постепенно, по одной карте.

Скачать все 78 сканов локально: `python scripts/fetch_cards.py`.

Настройки: `SEND_CARD_IMAGES` (выключить целиком), `IMAGE_CARDS_LIMIT`
(со скольких карт картинки не отправлять — по умолчанию больше трёх).
Перевёрнутые карты показываются тем же изображением, положение указано подписью.

### Языковая модель

Разбор собирает любой OpenAI-совместимый провайдер: бот шлёт
`POST {AI_BASE_URL}/chat/completions`. Сменить провайдера — это три переменные
окружения, код при этом не меняется:

| Провайдер | `AI_BASE_URL` | `AI_MODEL` |
| --- | --- | --- |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai` | `gemini-2.5-flash` |
| Groq | `https://api.groq.com/openai/v1` | `openai/gpt-oss-120b` |
| OpenRouter | `https://openrouter.ai/api/v1` | модель с суффиксом `:free` |
| xAI (платный) | `https://api.x.ai/v1` | `grok-4` |

У первых трёх есть бесплатные тарифы — лимиты уточняйте у провайдера, они меняются.
Имена моделей тоже меняются: провайдеры выводят старые из обращения, и тогда в `/diag`
появляется ошибка «model not found». Актуальный список — в документации провайдера.

Почти все современные модели — рассуждающие: часть лимита токенов уходит на внутренние
размышления, и видимый ответ оказывается короче. Поэтому `GROK_MAX_TOKENS` по умолчанию
3000: при 1200 разбор обрывался на полуслове.
Старые имена `XAI_API_KEY`, `XAI_BASE_URL`, `GROK_MODEL` продолжают работать.
Ключ живёт только на сервере и в репозиторий не попадает.

Системный промпт (`bot/services/interpreter.py`) запрещает модели фатализм,
предсказания смерти, болезней, диагнозов и исходов судебных дел — в таких темах
она мягко отправляет к профильному специалисту. К каждому авто-разбору бот
добавляет пометку, что расклад носит развлекательный характер.

### Безопасность и ограничения

- Карты тасуются `secrets`-случайностью, без повторов внутри расклада.
- Весь пользовательский текст экранируется перед отправкой в HTML-режиме.
- Антифлуд: не чаще одного действия в 0.7 с на пользователя.
- Лимит авто-раскладов в сутки (`DAILY_AUTO_LIMIT`), одна открытая заявка на человека.
- Админские действия закрыты фильтром `IsAdmin` (список id + админ-чат).
